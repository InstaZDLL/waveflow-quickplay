# WaveFlow QuickPlay 1.1.0

A macOS app, repeat and shuffle in the playlist, a hand-over to WaveFlow, cleaner DSD, and the player now decodes through exactly the same code as WaveFlow Desktop.

## New

- **macOS app**: a disk image with one app for Apple silicon and Intel Macs, macOS 11 or later. Finder offers it under *Open With* for every format it plays, DSF and DFF included, and it can be made the default player from *Get Info*. Until now macOS meant building from source.
- **Repeat and shuffle** in the playlist toolbar. One press on repeat loops the playlist, a second loops the current track, a third turns it off. Shuffle plays every track once before any comes round again, and Previous walks back through what played. Both are remembered, and `R` and `H` toggle them from the keyboard.
- **Continue in WaveFlow**: a button with the WaveFlow logo hands the queue, the current track, the position and the play or pause state over to WaveFlow Desktop, then QuickPlay closes. WaveFlow picks up at the same spot. The button appears only when WaveFlow Desktop **2.0.0-beta.1** or later is installed, so it stays hidden until that version is out.
- **Long lyric lines keep up with the song**: a line wider than its column holds for a moment, then scrolls so that its end is on screen before the next line starts.
- **A shorter title bar** that reads *QuickPlay* beside the WaveFlow logo, which leaves more room for the track's title. The file-manager entries are shortened the same way, to *Play with QuickPlay* and *Add to QuickPlay playlist*, in all eight languages.

## Fixed

- **DSD no longer hisses.** DSF and DFF files are converted with WaveFlow Desktop's 256-tap filter instead of 64 taps, which let the DSD shaping noise through as a steady hiss in the background.
- **Explorer menu order**: *Play with QuickPlay* now comes above *Add to QuickPlay playlist*. The installer removes the old entry.
- **A brief audio stall no longer stops the track.** A buffer underrun, such as the one macOS causes while it checks a new app on its first launch, was taken for a lost output device: the engine was released and the track stopped with an error. Playback now carries on.
- **A slow file no longer freezes the controls.** A track on a network share or a disk that is spinning up opens in the background, and Stop, another track or closing the window answer at once. Files on a network share are read ahead, so a seek there does not wait for the whole transfer.

## Under the hood

QuickPlay now plays through `waveflow-core`'s playback module, the decoding WaveFlow Desktop itself uses, instead of a copy of it. A decoding fix made for the desktop reaches QuickPlay with the next core update. What QuickPlay keeps of its own is the small transport around it: the decoder thread, the lock-free ring and the audio callback.

## Install

- **Windows**: download `waveflow-quickplay_1.1.0_x64-setup.exe`. It installs for the current user without administrator rights and registers the context-menu entries. Run it over 1.0.0 to upgrade; your settings live in their own file and are kept.
- **Linux**: the `.deb` for Debian and Ubuntu, the `.rpm` for Fedora, RHEL and openSUSE, or the `.AppImage` for any distribution (make it executable and run it). All three carry the desktop entry, so QuickPlay appears in "Open with" for audio files.
- **macOS**: download `waveflow-quickplay_1.1.0_macos-universal.dmg`, open it and drag *WaveFlow QuickPlay* to Applications. The app is signed ad hoc, not by an Apple Developer ID, so macOS blocks the first launch: open System Settings › Privacy & Security and choose *Open Anyway* (on macOS 14 and earlier, right-click the app and choose *Open*). This is asked again for each new version you download, since every release is signed anew.

SHA-256 checksums are in `SHA256SUMS-windows.txt`, `SHA256SUMS-linux.txt` and `SHA256SUMS-macos.txt`.

> [!NOTE]
> The Windows installer is signed with WaveFlow's self-signed certificate, so Windows may still show a SmartScreen warning on first launch.

## Known limitations

- On macOS, Finder has no per-app menu entries, so there is no *Add to QuickPlay playlist* there; *Open With* replaces the queue, as *Play with* does on Windows.
- **Continue in WaveFlow** needs WaveFlow Desktop 2.0.0-beta.1 or later, read from the install's metadata. The button stays hidden for an older WaveFlow, for one whose version cannot be read (such as an AppImage put on `PATH` by hand), and for the Flatpak build, whose sandbox cannot see the hand-over file.
- On Wayland the playlist window opens where the compositor places it and does not follow the player; the protocol does not let an application position its windows.
- The output device is the system default, opened in shared mode.
